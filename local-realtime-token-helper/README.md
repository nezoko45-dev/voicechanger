# Local Realtime Token Helper (Windows)

This helper replaces the hosted Vercel/Netlify token backend for the OpenAI Realtime Voice Reader.

## What it does

- Runs a small HTTP listener on `127.0.0.1:32145` only; it does not listen on your network.
- Keeps the OpenAI API key in the helper process memory and does not write it to disk.
- Requests a short-lived Realtime client secret from OpenAI when the reader starts.
- Allows browser requests only from `https://nezoko45-dev.github.io` (plus its own local origin).
- Does not save the key in browser local storage or in the repository.

## Build/download

The GitHub Actions workflow `.github/workflows/build-local-token-helper.yml` builds a self-contained Windows x64 executable. After the workflow completes:

1. Open the repository's **Actions** tab.
2. Open **Build local Realtime token helper**.
3. Open the successful run and download artifact **VoiceReaderLocalTokenHelper-windows-x64**.
4. Extract the ZIP to a folder you control.

The artifact is generated by GitHub Actions; it is not committed to the repository.

## Run

1. Double-click `VoiceReaderLocalTokenHelper.exe`.
2. Paste your OpenAI API key into its console prompt and press Enter. The prompt is visible while typing; do not screen-share or stream it.
3. Keep the console window open.
4. Open the Voice Reader GitHub Pages page and click **Start voice conversation**.
5. Allow microphone access if Chrome asks.

The reader calls `http://127.0.0.1:32145/api/session` automatically. No Vercel or Netlify URL is needed.

## Troubleshooting

- **Could not start / connection refused:** make sure the helper window is still open and says it is ready at `http://127.0.0.1:32145/api/session`.
- **403 from local helper:** open the official GitHub Pages reader at `https://nezoko45-dev.github.io`, not a downloaded HTML file or a mirror.
- **OpenAI error:** verify that the key is an OpenAI API key and that API billing/usage is enabled for the account.
- **Port already in use:** close any older helper window and restart it.

The key is held in memory while the helper runs. Closing the helper clears it from the process. API usage is billed separately from a ChatGPT subscription; use a dedicated API key and set appropriate usage limits.
